# 0031: Counting opens of the app link, and scans of the QR code

**Date:** 2026-09-29 · **Status:** Active · **Source:** Kat, 2026-09-29:
*"The QR code though needs to track # of scans and can someone confirm that
apple will tell us how many downloads happen by date?"*

## What we chose

1. The QR code now encodes `https://fxe-tennis-admin.vercel.app/app?via=qr`
   (regenerated by `scripts/make-qr.swift`, read back by Core Image and by
   Vision). The link written under it stays the short `/app`, so a typed or
   emailed link is counted apart from a scan.
2. `/app` sends one beacon per open to the `app-visit` edge function with
   only `{"via": "qr" | "link"}`. The database keeps one row per New York
   day and source with a count (`app_link_visits`, `20260929000005`):
   no IP address, no device, nothing about the person, so there is nothing
   to disclose in the privacy policy beyond a count.
3. Tara reads the totals on her Players tab beside the QR link
   ("opened 12 times, 9 by scanning"); `admin_app_link_visits` returns the
   rows per day for anything finer later.
4. **Downloads by date are Apple's**, not ours: App Store Connect →
   Analytics shows first-time downloads per day once the app is on the App
   Store; for TestFlight, the TestFlight tab shows each tester's status and
   installs per build, not a daily chart. Between the two, a scan count here
   and Apple's downloads there tell the story: scanned, then installed.

## Rejected

- **Vercel Web Analytics or any third-party tracker**: a script from
  someone else on the page members open, a dashboard Tara would not look at,
  and more data than a count. Ours is 40 lines and says exactly what it keeps.
- **Counting on the server by request logs**: Vercel serves `/app` as a static
  file; there is no log we own.

## How we would know this was wrong

The count is public to write: anyone who finds the function can inflate it
(the worst case is a wrong number, never a leak). If a number ever matters
for money or a decision, add a per-day cap or move the count behind a
signed token.
