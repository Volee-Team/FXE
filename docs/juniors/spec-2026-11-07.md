## 01 / Purpose and shared parent setup

**Goal:** Keep registration easier than texting Tara and sending a separate
payment. Build on the existing adult app and website; preserve current adult
behavior.

**Scope:** School-year junior sessions, approved drop-ins, summer camp, treats,
attendance and billing. Pool, court reservations and Volee integration are
future work, outside this update.

### One-time family setup

Sign in / Create account → Profile → My Children → Add a Child. Collect child
name and birthday. Support multiple children. Existing adult users retain their
account, contact details and saved card.

Parents can browse before payment setup. Require a parent-signed waiver for
each child and a saved card before completing registration. Notifications go to
the parent.

Support separate parent logins linked to the same child. Each booking must
identify the paying account/card; avoid duplicate child profiles.

### Program selection is always manual

| Program | Suggested ages / approval |
|---|---|
| Red Dot | Ages 3-6; no program approval |
| Orange Dot | Ages 6-10; no program approval |
| Recreational Yellow | Ages 10+; no program approval |
| Junior Elite | Tara approval required |
| Elite | Tara approval required |

Show Tara's program descriptions and age guidance. Never assign a group
automatically from a birthday.

Junior Elite and Elite approvals are specific to the program and carry between
school-year and summer offerings. Tara can preapprove current players.

## 02 / School-year sessions and drop-ins

### Full-session registration

Choose child → Program → Register for Session → Review schedule and price →
Confirm and pay.

Charge the full session amount upon confirmed registration. Elite programs
require program approval first; other groups do not.

Tara sets a cap per program. Full-session enrollment reserves that child's
place on every included class date. When full, show Request a Session Spot;
take no payment until a place is offered and accepted.

### Joining a session late

Request remaining session → Tara enters prorated amount → Parent reviews and
accepts → Confirm and charge. Allow joining a week or more into a session when
space allows. Do not require an automatic prorating formula.

### Drop-in registration

Choose child → Program → Select one or more dates → Request Drop-In. Every date
requires Tara's approval, including for already-approved Elite players. Pending
requests do not reserve capacity.

Requests remain open until the class starts, including when a roster is full.
Tara approves or declines each date. Approval confirms attendance without
requiring a second acceptance step at the originally displayed price.

After submitting, show optional Text Tara for Faster Approval. Open a prefilled
message in the parent's texting app; the parent presses Send. Include child,
program, date and time. The text does not confirm a spot or create another
request.

### Absences, cancellations and rainouts

| Situation | Rule |
|---|---|
| Session player absent | Parent can tap Can't Attend for that date. No refund or price adjustment. Show the absence so Tara can consider a drop-in. |
| Approved drop-in cancels | Free any time before class starts. Update roster and notify Tara. |
| Drop-in attends / no-show | Bill after class. No-show is billable; canceled drop-ins are not. |
| School-year rainout | Tara messages the entire group with the makeup date. |

Show confirmed session players, reported absences and approved drop-ins against
each date's cap. Pending requests remain separate; Tara controls admission and
any capacity override.

## 03 / Summer booking and registration windows

### Summer parent flow

Choose child → Program → Full Week or Choose Days → Review dates, rates and
treats → Confirm.

Allow scattered dates across the summer, such as every Thursday. Parents should
not repeat account setup for each booking.

A full-week selection reserves individual scheduled days. It does not create an
upfront weekly charge. Junior Elite and Elite may run only 2-3 days per week;
show only dates Tara schedules.

Below the cap, confirm automatically. Junior Elite and Elite require existing
program approval; approved school-year players do not ask again for summer.
Camp dates can be booked until their start time.

| Summer program | Daily cap |
|---|---|
| Red Dot | 25 |
| Orange Dot | 50 |
| Recreational Yellow | 25 |
| Junior Elite / Elite | Separate caps set by Tara |

All caps are editable ceilings. A full group shows Request a Spot, with no
charge while pending. Tara may admit an additional camper if staffing allows. Do
not automatically move someone into a billable booking from a request without a
clear confirmation process.

### Registration opening dates: configurable

| Offering | Opening rule |
|---|---|
| School-year full sessions | Tara sets separate member and nonmember dates AND times. |
| Summer camp | Tara sets separate member and nonmember dates AND times. |
| School-year drop-ins | Same access for members and nonmembers; Tara approval required. |

No fixed four-day rule. Tara can open both groups together or give members any
lead time. Display the correct opening information to each parent. Do not apply
the adult weekly registration windows to junior offerings.

### Summer cancellation

Free cancellation at least 12 hours before that day's start. Late cancellations
and no-shows are billable, with Tara's ability to waive or reduce. Apply the
rule to each day even within full-week bookings.

For bookings made inside the 12-hour window, clearly state that the free
cancellation deadline has already passed. Cancellations update daily headcounts
and availability.

## 04 / Summer rates, sibling discounts and treats

### Program-specific prices with daily flexibility

Each program has its own published price. School-year and summer rates can
differ. Tara can edit every child's final amount before billing, including
partial-day charges and individual deals. The default rate should cover most
campers so only exceptions need editing.

### Daily sibling discount

When siblings attend on the same day, the first child pays their program rate
and each additional sibling gets $5 off. Apply across summer programs and
separately placed bookings. The earlier $10 discount for the third child is
superseded.

| Example at $50/day | Camp charge |
|---|---|
| First child | $50 |
| Second child | $45 |
| Third child | $45 |
| Total | $140 |

Calculate against actual same-day attendance, not merely the number of children
in the account. Handle linked parent accounts as the same family. The
first-child ordering and interaction with custom rates need a consistent rule;
see final page.

### Treat permission: quick and optional

For each child, parents choose No Treats / 1 Treat / 2 Treats per day. Remember
the selection and allow changes for individual dates. Show treat prices when
permission is given.

Staff sees the daily allowance and records how many treats were actually given.
Charge only for treats given, up to the authorized count. Do not use a prepaid
balance or dollar-limit workflow. Staff cannot change prices or charge a card.

### Payment authorization

Parents authorize the selected program rate and separately authorize treats.
Tara can charge less without another approval. Any charge above the agreed camp
amount, or treats beyond the authorized selection, requires explicit parent
approval in the app before charging.

The $50 ceiling discussed was an example for $50 regular camp, not a universal
limit on differently priced Elite programs. Show and retain the agreed amount
for each booking, discounts and authorized extras.

Suggested payment-agreement requirement: Never charge more than the parent's
authorized amount without a recorded approval-button action. Tara may reduce
charges for partial attendance at her discretion; partial attendance does not
automatically guarantee a reduced rate. Final waiver/payment wording still needs
review.

## 05 / Pros, walk-ins and Tara's daily billing

### Pros: weekly visibility and daily attendance

Extend the existing pro Today view with a week view. Show Monday-Friday summer
tabs, future weeks, names and daily headcounts grouped by program. School-year
rosters also show Session or Drop-In. Keep lists current as families book or
cancel.

Pros can see child names, ages and parent contact information; mark Came /
No-show; see reported absences and cancellations; and add walk-ins. Keep pending
requests separate from confirmed attendees.

### Walk-in capture

Add Walk-In → Select existing child OR enter child name, parent name and parent
phone → Record attendance. Include an optional note. A child can be recorded
without the parent completing signup courtside.

New walk-ins go to Tara's Action Needed list as Payment follow-up needed. Tara
follows up for account setup, waiver and card. Link captured attendance to the
eventual child profile without duplicating the attendance or charge. Do not
charge a new walk-in without a saved card and applicable authorization.

### Only Tara controls money

Pros cannot edit camp rates, apply discounts, approve higher amounts or charge
cards. Treat recording uses preset prices and parent-authorized quantities; it
is not permission to change billing.

### Daily summer billing

Attendance marked → Tara reviews day → Adjust exceptions → Charge Today's Camp.
Include camp and actual treats in a combined daily payment where feasible, with
separate line items in history. Cover billable late cancellations/no-shows as
well as attendance.

Show each child's default price, sibling discount, custom adjustment, treats and
final total before processing. Do not treat unmarked attendance as confirmed
attendance automatically.

Clearly distinguish Uncharged / Paid / Failed / Needs Approval. Prevent
duplicate billing, including after partial batch failures. Failed payments
return to Tara's Action Needed list for follow-up.

### Parent records and messages

Parents see family bookings, child names, status, cancellations and itemized
payment history. Send relevant booking/approval and cancellation messages. Do
not send daily charge push notifications. Confirm payment-provider email receipt
settings separately.

## 06 / Admin setup, handoff checks and open decisions

### Tara's seasonal setup

Create and edit each program's description, dates, weekdays, times, excluded
dates, member/nonmember prices, session and drop-in pricing, summer daily
pricing, caps and registration opening dates/times. Support varying session
lengths, including six or nine weeks.

Manage program approvals, full-session requests, per-date drop-in requests,
full-camp requests, prorated offers, walk-in follow-up, messages, attendance and
daily billing. Message the appropriate program group for rainouts and makeup
dates.

### Keep the parent experience small

Reuse the existing app and website components where practical. Keep the child
name visible throughout registration. Show only relevant actions: Register for
Session, Request Drop-In, Request Approval, Book Camp or Request a Spot. Do not
expose admin configuration to parents.

Multiple children and dates should not require repeated setup. A combined family
selection screen is a useful design target, but must preserve each child's
manually selected program and individual dates/prices. Review actual mobile
screens with Tara before finalizing navigation.
